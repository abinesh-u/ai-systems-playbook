# Editorial Guidelines

1. Start from an approved knowledge-system node, gap, or source asset.
2. State audience, intended outcome, scope, and exclusions before drafting.
3. Record source assets and external references; do not turn a source mention into a claim.
4. Do not rewrite imported archive content. New work must live under `content/`.
5. Distinguish observed project evidence from reusable patterns and proposed guidance.
6. Link to prerequisite and follow-on concepts from the knowledge graph.
7. Use a template matching the content type.
8. Mark missing evidence, assumptions, and future validation explicitly.
9. Keep a single canonical page per concept; use supporting pages for narrower questions.
10. Run quality, review, and publication checks before release.
