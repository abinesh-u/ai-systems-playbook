# Writing Style Guide

Write for engineers who value precision.

- Lead with the engineering outcome or decision.
- Use plain language, short paragraphs, and descriptive headings.
- Define a term once; use it consistently thereafter.
- Explain mechanisms, constraints, failure modes, and trade-offs—not hype.
- Separate fact, inference, recommendation, and open question.
- Prefer concrete examples, interfaces, diagrams, and decision tables where useful.
- Use active voice and direct verbs. Avoid filler, rhetorical urgency, and superlatives.
- Preserve source wording only when quoting; otherwise attribute and link the source.
- Use sentence case headings; use code formatting for files, APIs, models, and commands.

Avoid: “revolutionary,” “game-changing,” unqualified “best,” vendor worship, fabricated metrics, and claims of universal applicability.
