# Diagram Guidelines

Use diagrams to expose relationships that prose cannot efficiently show.

- Give each diagram one question and a descriptive title.
- Label boundaries, inputs, outputs, ownership, and direction of flow.
- Separate control plane, data plane, and model/inference concerns when relevant.
- Use a legend only when symbols or colors carry meaning.
- Prefer editable source (Mermaid or source-controlled diagram definition).
- Do not use diagrams as decorative summaries or claim unverified implementation details.
- Verify every node and edge against the accompanying text and cited evidence.

Recommended types: flow for execution, sequence for interactions, component diagram for responsibility boundaries, and decision table for trade-offs.
